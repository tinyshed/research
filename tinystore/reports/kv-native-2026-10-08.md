A ratio above one means less native elapsed work for this identical operation trace. `get_bytes` uses typed bytes on both sides; `get_raw` compares an owned raw tagged value; `get_json` decodes the same document into owned fields. The native path black-boxes complete owning values/pages/documents before consuming them, and statements never lend bytes past reset. `getentry` consumes version text as well. `take_cycle` and `delete_cycle` include recreation, so they are two durable mutations per iteration. `clear_small` removes 256 spilled cells; `clear_mark` hides 10,001 cells; `expire` deletes 1200 spilled expired cells. Those one-shot cases have six independent file copies, not six repetitions against an already emptied branch.

The native slice has one synchronous writer and reader; it omits Go lifecycle/admission/reservation and grouped-commit scheduling. It keeps the original SQL rules and WAL/FULL commit semantics for these calls. Therefore these ratios measure an implemented native/backend/runtime slice against the complete public Go paths, not a pure language comparison. Mutating benchmark cases also compare final physical row snapshots after each paired run; revisions, values, expiries, spill references and orphan counts agree.

The read gains do not carry into durable writes: Set256, Take/Delete cycles and durable Add remain near parity, while the native 4 KiB spilled overwrite takes about 1.39 times the Go elapsed work. This round does not isolate filesystem/VFS synchronization from statement and writer-path costs, so it supplies no proven explanation for that regression. Clear/Maintain are intentionally one-shot measurements of roughly 7–12 ms and have visibly wider variation; they deserve less quantitative confidence than the calibrated loops. Every other matched repeatable sample exceeded 102 ms in this collection.

No SQL runs in these kernels.

## Wrapper, allocation and memory evidence

The SQL-only `sql_get` row is a prepared `select value from cells where bucket=1 and path=?1`, with one copied owning 256-byte result. Its paired Go/native elapsed ratio is 1.74×. Native safe-rusqlite/raw-C-API ratios by pass are 1.03; 1.03; 1.06; 1.05; 1.13; 1.13 (median 1.05×). The C-API control checks prepare/bind/step/reset/finalize return codes, bounds the result and copies it before reset. It is not the engine backend and supplies no evidence about other wrappers, writes or an optimized full engine.

This is a short-query wrapper control, not an exact isolation of every binding instruction: the C-API control explicitly steps to DONE, whereas safe query-row handling resets after obtaining its one row. The full engine's much longer hidden-branch SQL also passes through rusqlite's statement cache, which this control does not model. In particular, the 1.05× result cannot be generalized to mean the full engine pays only five percent wrapper overhead.

Go counters are runtime heap allocation deltas captured outside the timer. Rust allocation counters come from a separate instrumented binary; its elapsed timings are diagnostic only and excluded from every ratio. Rust global allocation counts exclude SQLite C mallocs, while Go runtime accounting includes its own driver/Wasm allocations. SQLite cache/status plus RSS cover additional resident memory; these are different accounting domains, not directly comparable total allocated-byte budgets. Native reader/writer cache hits, misses, writes, spills, resident cache bytes, statement bytes and commit counts are retained per run. Go SQLite counters are available only for its separate internal/sqlite SQL-control connection, because the public KV handle exposes none.

Whole-process peak RSS ranges across engine runs: Go 9.2–15.3 MiB; native 4.3–6.1 MiB. Current VmRSS/VmHWM snapshots before and after loops are retained separately. Peak RSS includes engine setup and caches, not just a returned value. It does not establish a production memory budget or the cost of concurrent readers.

The native compile-option inventory also differs in compiler, mutex/automatic-initialization support and maximum SQLite worker threads (8 native, 0 Go/Wasm). The scalar queries here request no parallel sort workers. Source IDs match; the complete retained inventories, rather than the word “matched,” define the precise configuration comparison.

## Correctness, limits and what follows

Rust unit tests pass path escaping/bounds, owned numeric bit retention and alternate key-kernel equivalence. The cross-language oracle compares 56 normalized API results and complete post-trace row snapshots. It covers empty/short/512/513/4096/1-MiB values, strings, signed/unsigned integer representations, -0 and float32/float64 signaling/quiet NaN payloads, JSON structs, deep/zero-containing owners, integer/text key identity, CAS conflicts, failed-Take rollback, expiry/DefaultTTL preservation and recreation, Touch version retention, small/marked Clear, maintenance and durable-counter overflow. Delete/expire/reopen preserve nonrepeating successful versions; an intentional rollback consumes a revision gap. 32 native-written numeric/raw shapes reopen through Go's typed API. Missing spill reads/takes report corruption and keep the cell. A four-MiB scan page stops after four one-MiB values, resumes for the fifth, and a value past one MiB is refused.

The failed-Take mutant was built in a temporary copied crate, without changing the measured source; removing its decode check makes the oracle observe a successful bad Take and missing key. [guard-proof.json](data/kv-native-2026-10-08/guard-proof.json) retains broken/restored transcripts and mutant hashes. Raw semantic/corruption traces and length/hash-compacted page-bound outputs are retained beside it. Source tests ran in Linux; Windows/macOS production CI, full TinyStore task check/race/SDK suites and complete native engine race/crash tests were not run because production code was unchanged and this slice does not implement those runtime paths.

Native keys/owners are valid UTF-8 text only; production Go permits arbitrary key bytes. Arbitrary byte values remain exact. Native error text is not identical: normalized sentinel category and exact bucket/path identity are compared. The slice relies on a Go-created migrated schema and omits directory locks, bootstrap/migrations, lifecycle/gates, process memory reservation, concurrency/grouped commits, cancellation, full transactions/views, custom codecs/panics, background work, sliding expiry, relaxed counters, configs/watch, once, limiter/quota and a cache runtime. Its SetIfAbsent is a synchronous single-owner implementation, not a concurrency promise. Full contracts, crash tests and grouped concurrency remain gates before using it as TinyStore.

The evidence supports continuing a native KV port with the original schema and typed/raw vocabulary. The key-escaping alternative is a separate Go/Rust optimization candidate and needs representative production key distributions before adoption. The next step is runtime/concurrency equivalence and bare-Linux service measurements, not multiplying these local ratios into a production throughput claim.
