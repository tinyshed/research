# The api's schema from axum's handlers, 3 November 2026

Chapter 13 asks for the crate that derives the api's OpenAPI schema from the hub's handlers to be measured before
one is taken: what it adds to the binary, and whether it reads axum's handlers as they are. Three routes shaped as
the hub's first slice serves them — `setup`, `instances` with a tagged `placement`, `run` with a decimal as text —
in four builds: plain axum, utoipa and aide each building the schema at start, and utoipa with the schema built
only by a test. Code in [`openapi-probe/`](../openapi-probe/), the schemas in `openapi-probe/out/`.

**utoipa, with the schema written by a test into a committed file the binary carries as text: nothing added to the
binary, the statuses a handler answers declared, and a current crate on schemars' side of no one.**

| Question | Answer |
|---|---|
| What does a schema built at start cost the binary? | utoipa +524 KB, aide +463 KB, over plain axum's 1.08 MiB |
| And built only by a test? | nothing: utoipa's marks on the handlers left the binary at 1 135 424 bytes, plain axum's to the byte |
| Does either read axum's handlers as they are? | aide reads a handler's `Json<T>` in and out; utoipa wants `#[utoipa::path(...)]` on each. Each added the same lines over plain axum, +30 and +28 |
| Is the schema right? | both OpenAPI 3.1, the tagged enum a `oneOf`, a doc comment a description; aide leaves a handler returning `StatusCode` with no responses, which need marks there too |
| Are they alive? | utoipa 6.0.0 of September 2026, 20.8 M downloads in 90 days; aide 0.15.1 of April 2026, 1.3 M, still on schemars 0.9 where schemars is at 1.2.3 |

## What follows for the hub

- A handler carries `#[utoipa::path(...)]` and its types `ToSchema`; the router is plain axum's.
- A test writes `openapi.json` from the handlers; the file is committed, the binary serves it as text at
  `/api/openapi.json` and prints it for `dashbin openapi`, and the test fails when the file and the handlers differ,
  Go Dashbin's `api:types:check` kept as a gate.
- A route's path is written once, in its mark, and the router takes it from there, so the two cannot drift; a test
  sends a request to every path of the schema and fails on one the router does not know.
