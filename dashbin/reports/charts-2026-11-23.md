# A chart library for Dashbin's page

23 November 2026. Stand: [`chart-probe/`](../chart-probe/), whose README holds the rule written before any
number was taken. Dashbin at `408a3b3` with its page's base uncommitted; nothing of Dashbin was built for this.

**The question.** Dashbin's page draws a line and bars. What it is measured against is a hand-made traffic page
on Chart.js: bars stacked by category over time, a click on the legend that hides a category, a dashed
threshold. Which library carries that at the least weight, and is any too slow?

## What was run

| | |
|---|---|
| Machine | AMD Ryzen 7 7700, 8 cores and 16 threads, 31 GiB, Windows 11 |
| Browser | Chromium 156.0.8078.100, the Claude desktop app's pane, the tab in front, device pixel ratio 1 |
| Runtime | Bun 1.4.5, `Bun.build` minified for the browser, gzip at level 9 |
| ECharts | 6.1, tree-shaken to bar, line, grid, legend, tooltip, mark line and the canvas renderer |
| Chart.js | 4.5, bar and line controllers and elements, the category and linear scales, legend, tooltip |
| uPlot | 1.6.32 |
| TanStack Charts | 1.5.0, its SVG host and its canvas host, both in the one bundle weighed |

Three cases of generated, seeded data in the shape of the traffic store's answers: `day`, 25 buckets × 6 series
as stacked bars; `week`, 1 008 × 6 as stacked bars; `line`, 8 640 × 6, 51 840 points, as lines. A draw is timed
from an empty element to two animation frames after the library returned, animation off; 9 draws after 2
unmeasured, in 3 passes, every library through every case before the next pass. The whole run was done twice,
the second after uPlot's stacking order was mended, and the second is reported; the first differed by under 2 ms
a median but for TanStack's SVG `week` (56–60 against 50–60).

**The method's floor is 20 ms**: two frames of this screen. A draw that costs nothing reads 20.0, so below that
the table says only "at the floor", and the `sync` column, what the call itself took before any frame, tells
those apart. uPlot and ECharts draw in a frame of their own, so their `sync` is not their whole cost; their
total at the floor bounds it under one frame.

## By the rule

The lightest that passes is **uPlot**: 23.2 KiB gzipped, 39 lines of ours, at the floor in every case.

## What the rule did not ask, found while drawing

The rule was written from the traffic page's three features, and drawing showed it left out what a dashboard
needs of any chart. None of this was measured; it is what each library's own interface shows.

- **A tooltip of every series at the pointer.** ECharts, Chart.js and TanStack Charts ship one. uPlot shows the
  values in its legend under the plot, and a tooltip is the page's to build on its cursor hooks.
- **Bars by a name, not by time**, which is what Dashbin's `bar` viz is: "numbers by the first column", laid
  down when the names do not fit. ECharts and Chart.js draw categories and horizontal bars as options;
  TanStack Charts has `barX`. uPlot's x axis is numeric, and categories on it are tick formatting and a path
  builder of ours.
- **The legend.** uPlot's is an HTML table of its own under the plot, which overflowed the panel here;
  TanStack Charts' are pill buttons with their own chrome; ECharts' and Chart.js's are painted on the canvas,
  where the page's CSS does not reach. Whichever is taken, a legend built by the page from its own tokens is
  likely, and then "built in" matters less than the call that hides a series, which all four have.
- **TanStack Charts is the newest by far**: its documentation says versions before 1.0 follow an alpha policy
  and to pin an exact one, while the package installed is 1.5.0; the two were not reconciled here. It is a
  grammar of graphics, marks over rows, which reads closest to a dashboard document a model writes, and it
  has a Svelte 5 adapter. It was the slowest of the four and passed.

## Not measured

- A WebGPU library, ChartGPU 0.4.0, was read and not drawn: its README says there is no WebGL or canvas
  fallback and that unsupported browsers are the host's to gate, which the plan's rule on choosing technology
  refuses before speed is asked. It lists stacked areas, not stacked bars.
- LayerChart, Svelte components over D3, was found and not drawn: the harness is plain TypeScript, and a
  second one for Svelte components was not built.
- Memory, a redraw on new data, a resize, twenty charts on one page, a phone.
- Any browser but Chromium 156 on one machine.
- The traffic store's real answers: the data is generated in their shape.
