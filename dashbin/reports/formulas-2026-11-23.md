# What a panel's formula is evaluated with

23 November 2026. Stand: [`expr-probe/`](../expr-probe/), whose README holds the rule written before any number
was taken. Dashbin at `d7cd8d5`; nothing of Dashbin was built for this.

**The question.** A panel is to compute from several reads: `fails / flows * 100` over rows joined by their keys,
kept where `flows >= 20`, and an alert is later to compare with the same language. Is that the Common Expression
Language, another library, a scripting language handed an eval, or a parser of ours?

## What was run

| | |
|---|---|
| Weight | static `x86_64-unknown-linux-musl`, fat LTO, one codegen unit, stripped, Rust 1.99.1, in the image Dashbin's `just size` builds in; each variant a binary alone with its own feature |
| Time | AMD Ryzen 7 7700, Windows 11, release build; a process that makes its rows and evaluates the formula and the condition over a million of them, five runs, the fastest; `plain`'s time taken off as the floor |
| `cel` | 0.16.0, without its default features, and with them: regular expressions, times, encoders |
| `evalexpr` | 14.0.0, no feature |
| `rhai` | 1.27.0, default features, only `compile_expression` used |
| `own` | `expr-probe/src/own.rs`, 194 lines before its tests, no dependency |

Every variant gave the same answer on 10 000 rows: 9 844 kept, their sum equal to the sixth decimal.

## What a formula can go wrong with

Values `fails = 5.0`, `flows = 200.0`, `zero = 0.0`, and no `absent`.

| Case | Ours | `cel` | `evalexpr` | `rhai` |
|---|---|---|---|---|
| `fails / flows * 100` | 2.5 | **fails at the row**: no `mul` of a Float and an Int | 2.5 | 2.5 |
| `fails / zero` | no value | `inf` | `inf` | `inf` |
| `fails / absent` | no value | fails at the row | fails at the row | fails at the row |
| `fails / flow`, a name that is no read's | refused as it is parsed, naming the reads | fails at the row | fails at the row | fails at the row |
| `5 / 200` | 0.025 | **0** | **0** | **0** |
| `fails = 1` | refused as parsed | refused as parsed | fails at the row | refused as parsed |
| `fails; flows` | refused as parsed | refused as parsed | **200**: the last of two statements | refused as parsed |
| `while true {}` | refused as parsed | refused as parsed | refused as parsed | refused as parsed |
| `exit(1)` | refused as parsed | fails at the row | fails at the row | **1** |

`cel` and `evalexpr` both name the variables a formula reaches before any row (`references().variables()`,
`iter_variable_identifiers()`), so a name that is no read's can be refused when a document is checked, by us.

## By the rule

| Line | `cel` | `evalexpr` | `rhai` |
|---|---|---|---|
| 300 KiB at most | **no**, 1 472 | yes, 196 | **no**, 2 544 |
| 10 000 rows in 5 ms | yes, 4.9, used with care | yes, 3.9 | yes, 3.7 |
| names known before any row | yes | yes | not tried |
| can only compute | yes | yes: no loop, an assignment refused by a context that is not mutable | **no**: a script, `exit` a function |
| a division by zero and a missing value told from a number | yes: `inf` is not finite, a missing name is an error | yes, the same | yes, the same |
| licence | MIT | AGPL-3.0-only, Dashbin's own | MIT or Apache-2.0 |

**`evalexpr` passes every line and is the rule's choice.** The parser of ours is lighter by 168 KiB, more than the
100 the rule lets a library cost for being a library, and the rule still takes the library that passes: it was
written to prefer a grammar others test.

`cel` fails on weight five times over. What was hoped of it, that a model already writes it, did not survive the
first formula: `fails / flows * 100` is an error in CEL, which never mixes an integer with a float, and a model
would have to be told to write `100.0`.

## What the rule did not ask, found while trying

- **A whole number divided by a whole number is a whole number** in all three libraries: `5 / 200` is 0. With
  every value of a read bound as a float this bites only a formula of literals alone, `1 / 2 * fails`, which is
  rare and silent. Ours has one kind of number.
- **`evalexpr` reads `a; b` as two statements** and answers the last. Harmless with a context that cannot be
  changed, and still not a formula: a `;` would be refused by us before it is parsed.
- **`evalexpr` brings what ours lacks**: `^`, `%`, `min`, `max`, `floor`, `round`, `abs`, and `if(condition, a, b)`.
  An alert's condition and a share of a total will want some of these, and each would be lines of ours.
- **A missing value is ours to handle with any library**: a row where a read has no value must come out empty,
  not fail. With `evalexpr` that is a check of the formula's names against the row before it is evaluated; in
  ours it is how a value is.
- **Messages.** Ours says where and what the reads are; a library's are its own words, to be wrapped.
- **Speed is no question**: the slowest that passes spends 4 ms on a panel's cap, and a read takes hundreds.

## Not measured

- Memory, and a formula a thousand terms long.
- Any formula over text or time: only numbers and truths were asked.
- `evalexpr`'s functions one by one, and how each treats a float it is given.
- How the join of several reads by their keys is built: this round is only the formula over a row.
